     - Builds a clean environment dict with `TERM=term`.
     - If `term == "xterm-ghostty"` and `infocmp xterm-ghostty` exits non-zero (common on `ubuntu-latest` where Ghostty
       is not installed), compiles a minimal `xterm-ghostty` entry (`use=xterm-256color`) into `tmp_path / "terminfo"`
       via `tic -o` (falling back to copying an existing `xterm-256color` compiled terminfo file into
       `tmp_path / "terminfo" / "x" / "xterm-ghostty"` if `tic` is absent) and sets `TERMINFO` in the returned env so
       `tmux attach-session` succeeds with genuine `TERM=xterm-ghostty` matching `xterm*:extkeys`.
   - Helper `_run_tmux_pty_capture(tmux_bin: str, term: str, payload: bytes, tmp_path: Path) -> bytes`:
     - Generates a unique socket name (`f"devenv-test-{os.getpid()}-{uuid.uuid4().hex[:8]}"`).
     - In a `try ... finally` block:
       - Starts a detached tmux session using
         `tmux -L <socket> -f <REPO_ROOT/dotfiles/tmux/.tmux.conf> new-session -d -s test -x 80 -y 24 <pane_cmd>` where
         `<pane_cmd>` invokes `sys.executable -c ...` to set stdin to raw mode (`tty.setraw(0)`), touch a `ready` marker
         file in `tmp_path`, read raw bytes from fd `0` using `select.select` until data arrives and settles (short
         post-read idle window, e.g., `0.15s`, with an overall bounded timeout e.g., `5.0s`), and write the captured
         bytes atomically to an output file in `tmp_path`.
       - Waits for the `ready` marker file (bounded timeout).
       - Allocates a real PTY via `pty.openpty()`, spawns `tmux -L <socket> attach-session -t test` connected to the
         slave fd (with `start_new_session=True`, `stdin=slave_fd`, `stdout=slave_fd`, `stderr=slave_fd`, and the env
         from `_ensure_terminfo_env(term, tmp_path)`), and closes `slave_fd` in the parent.
       - Drains initial attach output on `master_fd` briefly (using `select.select` so the PTY buffer never blocks and
         tmux finishes client capability negotiation, including `DA1`/`extkeys` startup).
       - Writes `payload` to `master_fd` and continues draining `master_fd` while waiting for the pane output file to
         appear (bounded timeout).
       - Returns the raw bytes captured by the pane.
     - In `finally`:
       - Terminates and waits on the attached client process if still alive.
       - Closes `master_fd` (and `slave_fd` if not yet closed).
       - Runs `tmux -L <socket> kill-server` (`check=False`, `capture_output=True`) so no stray server survives even on
         assertion failure or timeout.

     - Starts an isolated
       `tmux -L <unique-socket> -f <REPO_ROOT/dotfiles/tmux/.tmux.conf> new-session -d -s check "sleep 5"` inside a
       `try ... finally` block (calling `tmux -L <unique-socket> kill-server` in `finally`).
     - Asserts `returncode == 0` and `stderr.strip() == ""`.
   - Live parametrized PTY test `test_tmux_pty_shift_enter_and_enter_sequences(tmp_path: Path, term: str) -> None`:

     - Defines `EXTENDED_SHIFT_ENTER = {b"\x1b[13;2u", b"\x1b[27;2;13~"}`.

       3. ESC+CR (`b"\x1b\r"`): captured bytes `!= b"\r"` and contain leading ESC (`b"\x1b"`), e.g., `b"\x1b\r"`.
       4. Plain Enter (`b"\r"`): captured bytes `== b"\r"`.

## Risk Analysis

1. **Risk:** `tmux 3.4` (Ubuntu/WSL) rejects `extended-keys-format` with a stderr error if `-q` is missing.
   - **Mitigation:** Specify `set -sq extended-keys-format csi-u` and assert empty `stderr` on config load in
     `tests/test_tmux_shift_enter.py`.
2. **Risk:** `TERM=xterm-ghostty` fails to initialize in `tmux attach-session` on `ubuntu-latest` where Ghostty is not
   installed.
   - **Mitigation:** Detect missing `xterm-ghostty` terminfo via `infocmp` and compile/copy a temporary `xterm-ghostty`
     terminfo entry into `tmp_path` (`TERMINFO`), ensuring `TERM=xterm-ghostty` genuinely matches `xterm*:extkeys`.
3. **Risk:** Real PTY timing races or full master-fd output buffers cause flaky captures in CI.
   - **Mitigation:** Use an explicit `ready` file synchronization barrier from the pane reader, continuously drain
     `master_fd` via `select.select`, and use bounded timeouts with deterministic `finally` cleanup.
