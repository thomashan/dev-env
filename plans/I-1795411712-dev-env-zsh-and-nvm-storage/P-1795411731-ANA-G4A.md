## Risk Analysis

1. **Risk:** `find "$XDG_DATA_HOME/nvm" -maxdepth 1 -name "v*"` matches `versions` and creates a recursive symlink
   `~/.local/share/nvm/versions/node/versions -> ~/.local/share/nvm/versions`.
   - **Mitigation:** Restrict the `find` pattern to `-name "v[0-9]*"` and explicitly remove `$nvm_data/versions` if it
     is a symlink (`test -L "$nvm_data/versions"`).
2. **Risk:** Bi-directional symlinking between `~/.local/share/nvm/v*` and `~/.local/share/nvm/versions/node/v*` leaves
   the real directory behind when `nvm uninstall <ver>` deletes the symlink in `versions/node/`, causing `nvm` to
   recreate the symlink on next shell startup.
   - **Mitigation:** Migrate legacy real directories one-way via `command mv` into `~/.local/share/nvm/versions/node/`,
     delete any stale back-symlinks in `~/.local/share/nvm/v[0-9]*`, never create back-symlinks, and point
     `ansible/roles/node/tasks/main.yml` directly at `~/.local/share/nvm/versions/node/v{{ devenv_node_version }}`.

## Architectural Alignment

- Maintains `ansible/group_vars/all.yml` as the single declarative package manifest, using `devenv_pkg_skip` in
  `ansible/vars/os_Darwin.yml` for OS-provided binaries (`unzip`, `zsh`) and `ansible/vars/pkg_apt.yml` for
  Debian/Ubuntu package aliases.
- Unifies NVM storage across Ansible (`ansible/roles/node/tasks/main.yml`), `nvm.fish` (`$nvm_data`), and `nvm-sh`
  (`$NVM_DIR/versions/node`) so every shell reads, installs, and uninstalls Node versions from the exact same physical
  directory (`~/.local/share/nvm/versions/node/v<ver>`).
